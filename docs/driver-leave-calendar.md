# 司機日曆請假

日曆下方只有「排假」「當日臨請」「事後補請」三個入口；按下才展開。舊的申請主題切換、獨立日期清單、請假表單及申請進度卡片均已移除。

- 排假：先選假別，直接複選日曆中明天以後的已發布上班日；可跨月，最多 62 天。
- 當日臨請：日期固定為台北時間今天；選假別並填原因。已打卡時使用部分時段，不能申請整天。
- 事後補請：先選假別，再複選今天以前、已發布的上班日。有打卡的日期也能點選，但須填起訖時間補請部分時段；整天未打卡可留白補整天，不用等待系統生成未到紀錄。多日共用同一時段，時間須在各日班次內。
- 三種申請皆必填假別、原因，提供取消／遞交申請。已有待審或已核准重疊申請不能重複送審。休假及未發布班表不能請假。
- 多日補請先完整驗證日期，使用同一資料庫交易；任一日失敗，整批不寫入、不發送通知。每一日保留單獨的主管審核紀錄。
- 主管仍在「司機班表」審核，核准與拒絕皆必填回覆原因。日曆待審日期直接顯示「申請中」小標籤及滑鼠提示；圖例下方顯示當月申請中天數與不可重複申請說明，未展開表單時也能閱讀。主管審核後解除申請中標示，下方只顯示新的主管回覆通知，不重新加入舊申請進度卡片。
- 當日臨請及事後補請，即使核准，也保留原本「上班」班表與出勤稽核資料；日曆仍顯示上班。只有預排請假經主管核准才把班次改為「請假」。

新增司機 API：`GET /api/driver/leave-requests/makeup-candidates?from=...&to=...`（單次最多 62 天）、`POST /api/driver/leave-requests/makeup-batch`。身分固定取自 JWT，不能指定其他司機。

候選日期不以有無打卡鎖住上班日；GET 可帶 `leaveStart`／`leaveEnd`，按班次範圍與核准申請的時間重疊過濾。單日與多日 POST 皆接受這兩欄，有打卡卻未填時段時會提示具體日期且整批不寫入。待審日期即使不同時段也不可重複申請；核准的部分時段不重疊才可再申請。

前端日曆直接以當月已發布上班班次、日期方向及既有申請決定可選狀態，不再使用候選清單鎖日期，避免舊「整天未打卡」清單殘留使上班日不能點選。時間與打卡的最終資格在送出時由後端驗證。
