# 開發階段、時程、分工

目標展示日：**2026/09/21**（今日 8/15，共 5 週半）

## 分工

| 人 | 負責 |
|---|---|
| 演算法 | 距離矩陣介面（先假資料）→ OR-Tools 容量限制 → OSRM 架設 → 抽換為 OSRM |
| 後端 API | 資料模型建 Entity、門市／車輛／司機 CRUD、訂單流程、發布、報表計算 |
| 前端 1 | 路線規劃頁、拖曳調度看板 |
| 前端 2 | 門市主檔（Leaflet + Nominatim + 拖曳定位）、訂單匯入、司機端 |

前端不要等後端：先用符合 `docs/api-contract.md` 格式的假資料把畫面做出來，後端好了再抽換資料來源。

## Demo 主線（所有開發都是為了讓這條路徑跑得順）

1. 新增門市（地址查詢 → 拖曳定位）
2. 設定車輛與司機
3. 匯入當日訂單 Excel（故意放一筆錯的，展示被擋下）
4. 訂單審核確認
5. 執行排車 → 地圖顯示分色路線 + 指標卡
6. 拖曳一張訂單到另一台車 → 即時重算，顯示調整前後差異
7. 發布前檢查 → 發布
8. 切到司機端：看到任務 → 倉庫點交 → 填出車里程
9. 一鍵導航 → 確認交貨（拍照）
10. 演示無人簽收情境（原地等候 10 分鐘 → 配送失敗）
11. 回後台看即時車隊地圖
12. 收工填里程 → 報表顯示「計畫 vs 實際」

## 依賴鏈

```
主檔 → 訂單 → 排車 → 發布 → 司機端 → 報表
```

嚴格依序，任何一環卡超過一週會拖累後面全部，因此演算法（風險最高的環節）第一週就要開工。

## 階段規劃

### 階段 0：地基（8/15–8/17，全員）
- Repo、分支規則、`.gitignore`
- `docs/data-model.md`、`docs/api-contract.md`
- 前後端骨架跑得起來

### 階段 1：資料層（W1 後半）
- 門市／車輛／司機 CRUD API
- 門市主檔頁（地圖 + 地址查詢 + 拖曳定位）、車輛／司機頁

### 階段 2：演算法（W1–W2，與階段 1 平行）
1. 距離矩陣介面（先直線距離）
2. OR-Tools 階段一：距離 + 容量限制，能排出「哪台車跑哪些點、什麼順序」
3. OSRM 架設
4. 抽換矩陣來源為 OSRM + 存入資料庫快取
5. OR-Tools 階段二～三：時間維度、收貨時段

**W1 結束前必須看到 OR-Tools 吐出結果，哪怕用的是假距離。**

### 階段 3：訂單進系統（W2）
- Excel／CSV 匯入 + 後端驗證 + 預覽確認頁
- 後台手動建單（單筆表單 + 貼上文字框）
- 訂單審核

### 階段 4：排車主畫面（W2–W3）
- 路線規劃頁：指標卡 + Leaflet 分色路線 + 站點編號
- 串接排車 API

### 階段 5：調度看板（W3）
- Angular CDK DragDrop 拖曳改派
- 整包送後端重算、整包回傳重畫
- 裝載率變色提醒、調整前後差異對比表

**到階段 5 結束，PDF 題目要求的核心功能全部完成。**

### 階段 6：發布與司機端（W3–W4）
- 發布前檢查（未通過導回調度看板）→ 發布
- 司機端：任務清單、倉庫點交、里程填寫、一鍵導航、確認交貨、無人簽收、例外回報

### 階段 7：追蹤與報表（W4）
- GPS 定時回傳 + 即時車隊地圖
- 報表中心：計畫 vs 實際（Chart.js）
