# 車輛里程保養與退役

## 操作

- 人車資源 → **保養與退役規則**：設定同噸位共用的小保間隔、大保間隔、退役總里程，以及全車共用的提前提醒公里數（預設 500）。可以只填某個噸位；三項公里數都留白的列不套用。儲存會重新計算所有同噸位車輛，不修改過往保養紀錄。
- 新增車輛：只在第一次建檔時設定初始實際總里程；新車填 0 km，大小保初始基準自動為 0。導入舊車時可在首次建檔填入已知的初始保養基準。
- 編輯車輛：實際總里程與上次大小保里程全部唯讀；從資料庫自動讀取。司機收車後把結束儀表總讀數更新到車輛，主管不可透過畫面或 API 改高、改低或補數字。缺少快取時只從已綁定的司機完成里程／保養完成紀錄恢復，不猜測未綁定資料。
- 選 **送小保／送大保** 並儲存：自動建立一筆送修紀錄（時間、儀表里程、操作者），車輛不能派車。重複儲存同一狀態不會增加紀錄。
- 完成後改 **可用（保養／維修完成）** 並儲存：原狀態為小保／大保時，系統自動讀取資料庫當前實際總里程，記錄完成時間、里程，增加該類保養次數並更新基準。主管不手填保養里程；小保不重設大保，大保不重設小保。
- 取消送修：保留取消時間，不算完成，不更新基準。有歷史的車只能退役，不能刪除。
- 車禍、故障等非例行保養選 **送維修（車禍／故障）**，自動建立獨立 `REPAIR` 紀錄，在 **維修中** 分類查看。完成後改 **可用** 再儲存，才增加維修次數並記錄完成時間／當時實際里程。重複儲存不重複計次，取消維修不計完成；維修不算大小保、不重設大小保基準或汰換上限。人車資源顯示三種完成次數與上次完成時間，拖曳看板不顯示任何次數。

## 計算與出車卡控

`C` = 車輛目前真實儀表總里程 `currentOdometerKm`；不是 GPS 加入系統後累計值，也不是 OSRM。

`Bs`、`Bg` = 上次已完成小保／大保的儀表里程。

`Is`、`Ig` = 同噸位小保／大保間隔；`L` = 同噸位退役總里程；`W` = 提前提醒公里數。

```
現在距離小保 = Bs + Is - C
現在距離大保 = Bg + Ig - C
現在距離退役 = L - C

本次 OSRM D = 倉庫 → 全部配送站 → 原倉庫（含回程）
出車後預估剩餘 = 各項現在剩餘 - D
```

拖曳看板的草稿與發布卡片共用 `/api/dispatch/routes/{routeId}/metrics` 回傳的 `maintenance`，顯示「目前實際紀錄」及「本趟完成後（預估）」。有待配送單時，預估只計未完成訂單的含回程路程；全部結單後保留歷史路線里程，但不再當成新的待執行行程扣保養里程。拖曳改單先清除舊預估，儲存後以新路線重查；OSRM 未取得時明確顯示提示，不以 0 假裝。

任一預估剩餘 `< 0`：禁止排入／發布／開始出車，回傳超過公里數。

任一預估剩餘 `0 <= 剩餘 <= W`：提前提醒；剛好 0 不算超過。

全部 `> W`：正常。缺真實里程、基準、噸位規則或有效 OSRM 時不能通過預檢；保養中／已退役也不能派車。

收車輸入真實儀表里程後使用新 `C` 重新計算，OSRM 不寫入 `C`。資源或規則變更於資料庫交易成功後經既有看板頻道推播，兩個頁面重查同一後端資料。斷線重連也會重查。

## 資料庫

`V17__vehicle_repair_records.sql` 新增 `REPAIR` 紀錄類型，接續既有 `MAINTENANCE` 車輛為未完成維修。舊送修時間／里程未留存時保留 NULL，不推估；進行中紀錄不計次。大小保仍由資料庫 CHECK 要求送修時間與里程。既有維修完成或取消後使用相同記錄流程；不補假完成次數。本機套用前另已完整備份。

新增 migration：`backend/src/main/resources/db/migration/maintenance/V15__vehicle_maintenance_rules.sql`。Flyway 預設 migration 位置遞迴掃描此子目錄；沒有修改舊 migration。

`V16__recover_vehicle_mileage_from_records.sql` 僅從可確認車輛的已完成司機儀表紀錄與已完成保養紀錄補回快取，未綁定紀錄保留原樣，沒有資料的車不會自動假設 0 km。

本機使用者另已確認 `CAR-xxxx` 是示範資料，允許以 0 km 初始化。因此本機另套用 `db/demo/initialize_vehicle_maintenance_demo.sql`：只補沒有紀錄的示範車初始里程與大小保基準、缺少的噸位及示範週期，既有設定不覆蓋，保養次數保持 0。這不是 Flyway migration，不能自動套用到真實車輛。

本機舊 SQL 版本編號有重複且 `.env` 停用 Flyway，所以本次本機已先完整備份，再直接套用這一份 V15（未改 Flyway 歷史）。其他環境先確認遷移版本鏈與備份，再正常執行 Flyway／只套用尚未執行的 SQL；不要在已存在新欄位的資料庫重複手動執行。

保留舊車原始資料：只從明確的「數字噸」車型轉出噸位，不預填假儀表里程、假保養紀錄或未經主管設定的各噸位週期。
