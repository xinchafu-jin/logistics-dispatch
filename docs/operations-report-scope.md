# 主管營運報表：指標口徑與資料缺口

## 未結單訂單區（MAJOR）

第 04 區改為訂單處理進度，不再用待處理異常案件數當成訂單數。
以所選期間的預定配送日期篩選，依查詢當下狀態加總：
待確認（PENDING_CONFIRM）、待出貨（CONFIRMED／LOADED）、配送中（IN_DELIVERY）。
完成、取消、失敗、無人簽收屬於已結束配送原單；新建的重送／補送單依自己的狀態計入，避免重複計數。
三類互斥且加總等於未結單總數。點擊分類及明細連結，歷史查詢與 Excel 使用相同篩選。
訂單來源失敗顯示「—」，不假裝 0 筆；空結果才顯示沒有未結單。
異常案件功能與歷史紀錄仍保留，不更改案件的處理流程。

這份報表回答五個依序發生的問題：人能不能上班、車與路線能不能執行、訂單有沒有完成、哪些訂單尚未結單、問題集中在哪個出貨倉庫。首頁依此順序展示，歷史查詢保留逐筆核對與 Excel 匯出。

## 現在可核對的指標

| 指標 | 分子 / 分母或資料來源 | 解讀限制 |
| --- | --- | --- |
| 出勤率 | 已到班班次 / 已到應上班時間的上班班次 × 100% | 到班以打上班卡為依據。僅已發布班表，排除休假、核准整天請假及未來未到時間班次；缺卡不直接指控實際缺勤。 |
| 準時打卡率 | 準時打上班卡班次 / 已到班班次 × 100% | 不晚於應上班時間即準時，使用完整時間比較，不把遲到秒數截成 0 分鐘。核准部分請假涵蓋開始時間時，應上班時間延至請假結束；班表原樣不改。不是配送準時率。 |
| 加班班次率 | 下班超過排定下班至少 1 分鐘的班次 / 完成有效上下班打卡的班次 × 100% | 未收齊打卡、時間倒置或未來打卡不當成無加班班次。打卡延長時間不等同核准薪資加班。 |
| 已記錄加班分鐘 | 各有效完成班次：下班卡－max（排定下班、上班卡），扣除該段休息，負值為 0；各班取整分鐘後加總 | 司機資源「本月已加班」使用相同算法但期間固定為本月。只顯示有效上下班卡結算值；未下班與過去漏下班卡另外提示，不加總舊快取。不是薪資核准或司機端即時每 30 分鐘計入的數字。 |
| 實際出車 | 本期有真實出車開始時間的里程紀錄筆數 | 同車多趟／交接分段每筆分別計一趟；撤回發布不抹掉已發生的出車。不以已發布路線或車輛指派數當成出車。 |
| 收車完成率 | 有有效收車時間的出車紀錄 / 實際出車紀錄 × 100% | 包含本期正在執行趟次，不是準時收車率或整體車隊利用率；時間倒置、未來結束時間另列待核對。 |
| 已記錄實際里程 | 已完成趟次的 GPS 結算值加總；舊紀錄用可核對的儀表差值 | 同一趟不重複累加。缺紀錄留空，不用 OSRM 規劃数充當實際。明細與 Excel 保留來源；0 km 與未取得不同。 |
| 訂單完成率 | 已完成 / 可計算訂單 | 可計算狀態：已確認、已點交、配送中、無人簽收、配送失敗、已完成；排除待審核與取消。 |
| 待排率 | 已確認且待排車 / 可計算訂單 | 待排是目前狀態，不代表逾期。 |
| 配送異常訂單率 | 配送失敗或無人簽收 / 可計算訂單 | 訂單狀態；不得與異常案件數直接相加。 |
| 異常案件結案率 | 本期建立且已結案案件 / 本期建立案件 | 異常案件依建立日期，非訂單預定配送日期。 |
| 倉庫完成率 | 該出貨倉庫已完成 / 該出貨倉庫可計算訂單 | 不從門市地址推測配送區域。 |
| 各倉加總完成率 | 各倉已完成筆數加總 / 各倉可計算筆數加總 | 加權計算，不直接平均各倉的百分比。 |

每個大區塊標題旁顯示主要比例及統計母數，可點選查明細；人員用出勤率、車輛用收車完成率、訂單用完成率、異常用案件結案率、倉庫用加總完成率。訂單各狀態另顯示占全部訂單的百分比（此處含取消與待審核，與訂單完成率的分母不同）。規劃裝載率（規劃箱數／容量）留在路線明細與折疊的車輛規劃資料，不當成首頁實際營運績效；里程紀錄覆蓋／結算率是資料完整性，不再列為首頁車輛主要 KPI。

`/api/reports/performance` 以同一資料來源回傳整體與各倉人車比例、逐班出勤判定、逐趟出車收車及里程來源。列出倉庫主檔的全部倉庫，不因無訂單而隱藏。人員依司機**目前**所屬倉庫，非歷史歸屬快照；出車倉庫取已綁定的路線，舊紀錄只有在日期／司機／車輛唯一對應時才採用該路線。不能確認的另列「未歸屬／無法確認倉庫」，不以目前車輛倉庫猜測當時出貨倉。倉庫／司機／車輛篩選套用到其相關資料：車輛篩選只限制出車，人員不由車輛反推。未歸屬列的連結查全部明細供核對，不假裝套用一個不存在的倉庫。

歷史出勤、車輛分頁顯示相同指標與明細；Excel 額外保留「出車收車明細」「各倉人車比較」及母數。所有查詢唯讀，不改班表、打卡、請假或發布狀態。缺排定時間班次不硬算出勤率，另外提示主管核對。

比率沒有有效分母時顯示「—」，不顯示 0%。頁面依預定配送日期分組、讀取查詢當下的訂單狀態，因此舊日期的數字可能隨後續結案而變動；它不是某天當時的快照。所選期間若含未來配送日，已確認訂單也會列入完成率分母，介面會提醒其筆數。週別固定為週一至週日七天，週日公司休息，日長條圖僅顯示週一至週六；既有週日訂單仍保留於總覽及歷史明細，並提示其筆數。月度依自然週切分（4～6 週），月初與月底裁切在本月範圍內；不再把 22 日到月底併成一週。

## 暫時不能當成已實現的 KPI

- **配送準時率與 OTIF／完美訂單率**：需要保存承諾的配送時間窗、實際到達與簽收時間、應送與實送數量、破損及單據準確性，並定義部分完成與補送的處理。單憑 `COMPLETED` 狀態無法證明準時或足量。
- **實際每單／每公里成本與毛利**：目前只有規劃油費等估算，還缺實際油耗／加油、薪資工時、過路費、維修、折舊與收入歸屬。預估油費不可稱為實際成本。
- **車隊使用率與停駛率**：需要各日可用車母數、保養／維修停駛期間與實際發車紀錄。已發布路線上的車數不是使用率。
- **歷史時點回放**：目前訂單表保存最新狀態。要問「上週一當時有多少待排」需要狀態事件或每日快照。新版歷史頁的「本期對照前一期」是相同天數、不同預定配送日期的訂單，兩期都以查詢當下狀態重算，不能稱為當時的營運快照。

歷史頁可依日期、倉庫、門市、司機、車輛、路線 ID、異常類型與結案狀態查詢；訂單明細另可依狀態與關鍵字即時篩選。篩選條件依各後端資料源適用，不是所有分頁都支援每一項。前期比較套用倉庫、門市、司機與車輛，並在 Excel 的「前期比較」分頁保留口徑。變更需要重新查詢的條件後，舊預覽會標示過期且暫停匯出。
