# MAJOR 合併決議

整合 `feature/jin-route` 與 `murse-V2-all-v3`，依指定功能歸屬解決衝突。

## 保留 JIN

- 每台車的保養／退役規則、缺少保養資料時的提醒，以及含回倉的預估里程判斷。
- 出車前酒測與安全檢查、檢查通過後的出車里程，以及出車／點交的前後順序。
- 司機任務日期查詢、異常案件回報、路線偏離與後台處理。
- V1～V14 資料庫遷移，V12 移除噸位規則表與 `vehicles.tonnage`；不恢復 V2 噸位規則。

## 保留 V2

- 營運報表與歷史查詢：人員、車輛、訂單、異常、倉庫，支援日／週／月／年。
- 共用登入、主管導覽與畫面；人車資源司機分頁及所屬倉庫管理。
- 事後補請假：班表日曆、多日期、整日／部分時段、證明附件，以及審核紀錄。
- 司機班表與一般請假畫面完整採用 V3：日曆下方的排假、當日臨請與事後補請三個入口，保留跨月選取、申請中標示及審核回覆，不再混用 JIN 的一般請假分頁／表單。
- 途中無法繼續配送時的臨時請假與接手申請仍保留，在司機資訊分頁查看／申請，與一般請假日曆分開。JIN 的配送、出車檢查及支援中心不變。

## 整合接點

- 報表讀取 JIN 的安全檢查資料，只有同日、同司機、同車、同路線版本且未作廢的紀錄有效。
- 補齊事後補請候選日期與批次 API，日曆顯示待審申請與已選日期。
- 司機轉倉通知主管看板更新；新指派／發布以每條路線的所屬倉庫檢查。
- 配送進度與發布狀態分開，避免已結束的草稿被誤認為已發布。
- 新增 V15 `drivers.warehouse_id`，接續 JIN 結構。舊司機不猜測所屬倉庫，由主管指定。

## 資料庫注意事項

合併時先使用獨立測試庫驗證全套 Flyway 遷移與整合測試；本機原有 V2 資料庫另按下方的一次性程序補齊。
若現有資料庫套過另一分支同版號的遷移、手動新增欄位或保存不同 checksum，
部署前須備份並核對 Flyway 歷程，不可直接修 checksum 或讓兩組遷移同時執行。

本機合併提交不等於已部署或推送遠端。驗證輸出、測試資料庫工具及截圖不列入程式提交。

### 2026-09-28 本機 V2 → MAJOR 資料庫補齊

- 先完整備份原庫，在還原副本中完成結構、外鍵、索引、Hibernate 驗證與報表 API 整合測試，再停止本機後端套用原庫。
- 補齊 JIN 安全檢查、規劃分段、偏離路線、里程更正、司機異常回報與案件接手欄位，以及車輛個別保養規則。僅按已存在的噸位規則帶入已知數值；未知資料保持空白，不生成假檢查或打卡。
- 原噸位規則、舊安全檢查表、V2 Flyway 歷程改名為 `major_legacy_*` 保存，噸位欄位改名為 `legacy_v2_tonnage`，均不再供目前功能使用。原有 37 張表逐欄資料指紋核對一致；訂單、出勤、里程與請假資料不刪改。
- 結構核對後，建立明確標示「MAJOR verified V2 schema reconciliation」的 V15 baseline；沒有把 V2 歷程偽改成已執行 JIN 的 checksum。本機 `.env` 重新啟用 Flyway，後端啟動時再次驗證。
- 已知保留例外：2026-08-26，車輛 ID 2 同時有路線 ID 2（草稿）與 ID 3（已發布）；草稿仍有舊車輛分段紀錄。因此不刪除／改派路線，不強加 `uk_routes_date_vehicle`，須人工確認舊紀錄後再處理。其他必要索引、唯一限制與外鍵已核對。
- SQL 備份、設定備份、執行稽核與驗證收據保存於專案外的 `logistics-dispatch-db-backups/major-20260928-224000`。備份含私有資料，不能提交 Git 或當示範資料分享。

一次性結構核對工具為 `scripts/ReconcileMajorDatabase.java`，從 `backend` 目錄使用
`gradlew.bat -I ../scripts/reconcile-major-database.gradle majorDatabaseTool`，並明確提供
`-PdbMode`、`-PdbTag` 與專案外的 `-PdbBackup`。順序為 `prepare` → `rehearse` → `apply` → `verify`。
工具僅限本機 MySQL 與目前 V15，套用前要求成功副本收據、原庫無其他連線及新完整備份；
若選擇保留上述歷史路線衝突，副本與原庫須一致明確指定 `-PkeepLegacyRouteDuplicates=true`。
已修復的資料庫不能重複套用；`cleanup` 只清理已驗證的兩個測試副本，不刪原庫或備份。

歷史查詢的載入失敗狀態已修正：分頁保留、指出失敗的資料來源及連線／權限／後端錯誤，
提供重新載入入口；單一篩選目錄失敗不會清掉其他目錄，重新查詢時也不會匯出上一次期間的舊預覽。
